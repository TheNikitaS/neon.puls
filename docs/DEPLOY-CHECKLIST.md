# Деплой НЕОН.ПУЛЬС на виртуальную машину

Выбранный путь: **Ubuntu 24.04 + PostgreSQL + systemd + nginx, без контейнеров**.
Docker, Podman и `yc` CLI не нужны — виртуальная машина создаётся в консоли
Yandex Cloud.

## 0. Что получится

- Публичный адрес `http://<IP>` (или `https://ваш-домен` после подключения домена).
- PostgreSQL на той же машине.
- Приложение как служба systemd с автозапуском и перезапуском при падении.
- Nginx как reverse proxy на портах 80/443.

Время: 20–30 минут, из них ваших действий — 10.

## 1. Что нужно от вас

1. Аккаунт Yandex Cloud с **активным платёжным аккаунтом**.
2. Виртуальная машина (создаётся в консоли, шаг 2).
3. SSH-ключ (шаг 3).
4. IP-адрес машины и имя пользователя — прислать в чат.
5. Приватный ключ — положить в локальный файл `deploy/ssh_key`, **не в чат**.

## 2. Создание виртуальной машины

Консоль Yandex Cloud → **Compute Cloud** → **Создать виртуальную машину**.

| Параметр | Значение |
|---|---|
| Образ | Ubuntu 24.04 LTS |
| Платформа | Intel Ice Lake или AMD Zen |
| vCPU | 2 |
| RAM | 2 ГБ |
| Диск | 20 ГБ SSD |
| Публичный IP | автоматически |
| Имя | `neonpulse` |

В блоке **Доступ**:

- логин: `ubuntu`;
- SSH-ключ: вставьте содержимое публичного ключа (шаг 3).

В блоке **Сеть** → группа безопасности: разрешить входящие TCP **22, 80, 443**.

После создания скопируйте **публичный IP**.

## 3. SSH-ключ (делаете вы)

В PowerShell:

```powershell
ssh-keygen -t ed25519 -C "neonpulse" -f "$env:USERPROFILE\.ssh\neonpulse"
```

Появятся два файла:

- `C:\Users\<вы>\.ssh\neonpulse` — приватный ключ, **не отправлять**;
- `C:\Users\<вы>\.ssh\neonpulse.pub` — публичный, его вставляют при создании ВМ.

Приватный ключ скопируйте в проект:

```powershell
Copy-Item "$env:USERPROFILE\.ssh\neonpulse" "D:\Неон.Пульс\deploy\ssh_key"
```

Файл `deploy/ssh_key` уже в `.gitignore`.

## 4. Что прислать мне

Одним сообщением:

1. Публичный IP машины.
2. Имя пользователя (`ubuntu`).
3. Подтверждение, что ключ добавлен и файл `deploy/ssh_key` на месте.
4. Нужен ли свой домен (если да — какой).

## 5. Что сделаю я

1. Подключусь по SSH и проверю доступ.
2. Скопирую проект в `/opt/neonpulse`.
3. Запущу `deploy/install.sh`: пакеты, PostgreSQL, venv, systemd, nginx.
4. Проверю `/api/health`, вход, дашборд, AI-разбор.
5. Настрою домен и HTTPS, если он есть.
6. Пришлю ссылку и логи первого запуска.

## 6. Проверка после деплоя

```powershell
curl http://<IP>/api/health
```

Ожидается `{"ok":true,...}`. Затем:

1. Войти под `demo@neonpulse.ru` / `Demo2026!`.
2. Сменить демо-пароли в «Настройках».
3. Проверить дашборд: трафик, посмотревшие, вошедшие, купившие.
4. Внести тестовую выручку вручную и увидеть её в дашборде.

## 7. Обновления

```powershell
scp -i deploy\ssh_key -r app web ubuntu@<IP>:/opt/neonpulse/
ssh -i deploy\ssh_key ubuntu@<IP> "sudo /opt/neonpulse/.venv/bin/pip install -r /opt/neonpulse/requirements.txt && sudo systemctl restart neonpulse"
```

## 8. Безопасность

- Приватный ключ — только в `deploy/ssh_key`, не в чат и не в git.
- Пароль БД и секрет приложения лежат в `/etc/neonpulse.env` с правами `600`.
- После деплоя смените демо-пароли.
- Включите резервное копирование диска в Yandex Cloud.
- `NEONPULSE_SANDBOX=0` ставьте только когда подключите реальные камеры и кассы.
- Ключ YandexGPT живёт в `/etc/neonpulse.env` и не попадает в браузер.
