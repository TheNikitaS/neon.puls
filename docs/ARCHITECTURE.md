# Архитектура НЕОН.ПУЛЬС

## Слои

```
Клиент            SPA (web/) — кабинет компании и админ-панель платформы
API Gateway       FastAPI: JWT, роли, изоляция организаций, маршрутизация
Integration Hub   коннекторы Ivideon / POS / Custom REST → нормализация
Analytics Engine  KPI, динамика, сравнение, «до/после», аномалии
AI Engine         правила + адаптер LLM: выводы, рекомендации, объяснения
Notification      аномалии, состояние интеграций
Хранилище         PostgreSQL / SQLite: организации, точки, камеры, метрики,
                  чеки, изменения, выводы, рекомендации, эксперименты
```

## Поток данных

1. Коннектор забирает данные источника (или работает в sandbox-режиме).
2. Запись приводится к единому контракту:

```json
{
  "organization_id": "org_001",
  "location_id": "point_004",
  "source": "ivideon",
  "metric_type": "visitor_count",
  "timestamp": "2026-11-10T12:00:00Z",
  "value": 42,
  "unit": "persons",
  "metadata": {"camera_id": "camera_001", "zone_id": "entrance", "confidence": 0.95}
}
```

3. Нормализованные записи раскладываются по таблицам `attention_metrics`,
   `visitor_metrics`, `transactions`. Повторная синхронизация не перезаписывает
   уже собранную историю и не дублирует чеки.
4. Аналитическое ядро считает показатели по запросу (без материализации на MVP).
5. AI-ядро формирует выводы: факт → доказательства → уверенность → ограничения →
   рекомендация → план замера.

## Изоляция данных

Каждая сущность несёт `organization_id`. Контекст запроса (`deps.get_ctx`)
определяет пользователя, организацию и роль; `accessible_location_ids`
ограничивает выборку точками, разрешёнными роли и `scope`. Ни один роутер не
принимает `organization_id` из тела запроса — только из проверенного токена.

## Роли

| Роль | Ранг | Возможности |
|---|---|---|
| `ANALYST` | 10 | чтение данных и отчётов |
| `LOCATION_MANAGER` | 20 | + фиксация изменений и экспериментов |
| `REGIONAL_MANAGER` | 30 | + свои города и точки |
| `NETWORK_MANAGER` | 40 | + создание точек и камер |
| `ORG_ADMIN` | 50 | + сотрудники, интеграции, доступы |
| `SUPERADMIN` | — | вся платформа, админ-панель |

## AI-ядро

Расчётная часть детерминирована и не зависит от модели: правила сравнивают
периоды, считают конверсии, находят аномалии по z-score. LLM подключается
адаптером (`NEONPULSE_LLM_PROVIDER=llm`) и только переформулирует текст, не
меняя числа. Это позволяет менять провайдера без переписывания системы и
исключает выдуманные показатели.

## Коннекторы

`BaseConnector` задаёт контракт `test()` и `fetch(since, until)`. Реализации:

- `IvideonConnector` — видеоаналитика, зоны, события;
- `PosConnector` — универсальный REST с настраиваемым маппингом полей;
- `CustomConnector` — произвольный источник клиента.

Без ключей коннектор работает в sandbox-режиме и явно пишет это в журнал.
Добавление нового источника — новый класс и запись в `CONNECTORS`, без изменений
в аналитике и интерфейсе.

## Локальная ЦА и адрес точки

У точки есть адрес, район и профиль ЦА (`audience_segments`): сегменты, окна
активности, мотив и то, что может сработать. AI-ядро передаёт этот контекст в
каждое объяснение и проверяет, попадает ли пик входов в описанные окна
аудитории. Если не попадает — появляется вывод `audience_peak_mismatch`.

## Провайдеры LLM

`app/services/llm.py` поддерживает YandexGPT (Yandex Cloud Foundation Models)
и OpenAI-совместимый endpoint. Модель получает только готовые факты и
локальный контекст точки; числа считает детерминированное ядро. При
недоступности модели ответ строится правилами.

## Развёртывание

Для production: PostgreSQL (`DATABASE_URL`), reverse proxy с TLS, отдельный
секрет (`NEONPULSE_SECRET`), фоновые задачи синхронизации (Celery/APScheduler),
ограничение частоты запросов и резервное копирование БД.
